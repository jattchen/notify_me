Top recommendation

把通知编排收进一个深 Runtime

调用者只表达条件已经满足；Runtime 内部吸收效果解析、事件身份、SQLite 账本、去重升级、租约、Outbox 与 Bark payload 顺序。

Notification Runtime Strong

避免把每张表、每次 claim 和每个发送步骤暴露成浅接口。Skill、CLI 与 Hook 恢复入口都调用同一 Runtime。

Notify / Resolve
→
identity + policy + ledger + outbox
→
Bark transport
  • 故障和事务顺序保持 locality；
  • 去重、升级与订阅消费不能被调用者拆开；
  • SQLite 留在模块内部，不公开 repository/table 接口。

Activation Strong

把 Onboarding、私密 Bark 绑定、生效 AGENTS 文件解析、双 Hook 信任与新任务验证收进一个可恢复状态机。

  • inspect 只读，initialize 单独建库；
  • 规则只在一次明确授权后写入实际生效文件；
  • UserPromptSubmit 与 SessionStart(^compact$) 共享恢复入口；
  • 新顶层任务验证完成前不宣称 active。

Bark Transport Worth exploring

Bark HTTP 是真实外部边界，值得保留一个窄 adapter seam；确定性测试 adapter 用于失败分类、重定向、超时和 payload 合同测试。

  • Runtime 不依赖 HTTP 库细节；
  • 测试无需 patch 网络库内部实现；
  • 只报告“服务已接受”，不冒充手机已展示。

Effect Policy Keep internal

效果配置目前只有 Runtime 一个真实调用者。校验、解析、指纹和打扰强度比较应先作为内部实现，避免为了字段映射制造浅模块。

  • 效果指纹与打扰强度分开；
  • 只有严格更强或语义状态变化才自动升级；
  • 出现第二个独立调用者时再重新评估抽取。
