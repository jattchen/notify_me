# Notify Me 用户订阅与优先级配置

本 effort 将 `SPEC.md` 第 19.3 节已确认的开工基线实现为可迁移、可测试的端到端能力。实现保持现有 Blocking/P1 与 Severe Risk/P0 无 Hook快路径兼容，并逐步增加配置、订阅状态机与双 Hook 恢复。

## 交付顺序

1. 优先级与效果配置模型。
2. 当前任务作用域的订阅管理。
3. 订阅触发、消费、失败恢复与通知事项可靠性。
4. 双 Hook 最小上下文恢复。
5. Onboarding、doctor、发布与真实验收。

每张工单都必须保持现有测试通过；涉及 schema 的工单必须提供从当前 schema 的原子迁移和结构校验。
